# TBDev Yuna Scatari Edition

Ветка `php85-utf8` рассчитана на PHP 8.5 и MySQL-совместимую БД. Проверена с PHP 8.5.12 и MariaDB 13.0.2. Нужны расширения `mysqli`, `mbstring`, `iconv` и `openssl`. Для CAPTCHA и изображений требуется `gd`.

## Локальный запуск

1. Создайте отдельную пустую БД с кодировкой `utf8mb4`. Импортируйте `install/database.sql` **только в пустую БД**. В файле есть `DROP TABLE`.
2. Создайте `include/secrets.local.php` с параметрами `$mysql_host`, `$mysql_user`, `$mysql_pass` и `$mysql_db`. Для Unix-сокета укажите хост в форме `localhost:/path/to/mysql.sock`. Используйте соединение `utf8mb4` из `include/secrets.php` и проверьте, что в локальном файле нет старого переопределения `$mysql_charset`.
3. Создайте `include/config.local.php` с новой случайной `$_COOKIE_SALT` и `$site_url = 'http://127.0.0.1:8585';`. Проверьте, что каталог `torrents/` доступен серверу для записи. Локальные настройки и файлы раздач исключены из Git.
4. Запустите `php -S 127.0.0.1:8585 -t . dev/router.php` из корня проекта. Это сервер для разработки.

## Обновление существующей базы

Остановите запись приложения. Сделайте резервную копию БД и каталога `torrents/`. Восстановите копию в отдельную БД и подключите её в `include/secrets.local.php`.

```sh
php migrations/2026-utf8mb4.php
php migrations/2026-utf8mb4.php --apply
```

Первая команда печатает план. Вторая переводит `peers.peer_id` в `VARBINARY(20)`, затем перекодирует текстовые столбцы известных таблиц и устанавливает `utf8mb4` для базы. Формат `torrents.info_hash` и файлы `.torrent` сохраняются. DDL фиксируется пооперационно. При ошибке сверяйте выполненные команды с планом и при необходимости восстанавливайте копию.

План использует объявленные кодировки столбцов. Если в старом дампе UTF‑8 байты были сохранены как CP1251 или другая кодировка, такие поля требуют отдельного разбора на копии данных. Проверьте кириллицу в названиях и путях, идентификаторы и счётчики до переключения действующего сайта. При скачивании трекер меняет адрес announce, а блок `info` отдаёт побайтно.

## Проверка совместимости

`tests/legacy_tracker.py` пишет тестовые данные. Используйте его на отдельном локальном экземпляре MariaDB с пустой БД `tbdev_legacy`, созданной с `CHARACTER SET cp1251 COLLATE cp1251_general_ci`. Импортируйте в неё исходную схему из коммита `46c3c6c`, задав клиенту `--default-character-set=cp1251` и сессионный режим `NO_ENGINE_SUBSTITUTION`. Настройте PHP-стенд на эту БД и запустите его на `127.0.0.1:8585`. Клиент `mariadb` в проверке входит по Unix-сокету от имени текущего локального пользователя.

```sh
python3 tests/legacy_tracker.py prepare --socket /path/to/mysql.sock
php migrations/2026-utf8mb4.php --apply
python3 tests/legacy_tracker.py verify --socket /path/to/mysql.sock
```

Проверка сравнивает старый блок `info` и его SHA‑1 до и после скачивания, сверяет бинарные ID пиров и накопленный трафик после миграции, затем выполняет `started`, обновление, повтор обновления, `completed`, `scrape` и `stopped` для трёх режимов учёта. Она также проверяет вход с паролем, сохранённым в CP1251, загрузку через веб-форму и заголовок RSS с Unicode.
